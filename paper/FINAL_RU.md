## реферат (аннотация по ГОСТ 7.32-2017)

объект исследования: детерминированный headless планировщик tcp портов, у которого тик задают рефлекс скорости тела и детектор, а метку в режиме bio задаёт сокращённый readout из шести скаляров модели коннектома *C. elegans* (279 нейронов, вендоренный движок petri v1.2, commit 42d5062). цель: установить, даёт ли метка из readout измеримое преимущество перед сеяным xorshift64* и случайным, и что из заявленного выдерживает проверку артефакта. методы: парные партии с журналом (100 сидов на режим по 600 s), пассивная метрика обучаемости L, held out порядок 1 (n = 20 журналов на семейство, bootstrap 95%), order 0 baseline, восстановление генератора, калибровка детектора на замороженной процедуре. результаты: каталог опровержений. порядок 1 log-loss даёт 5.851 у bio против 6.025 у random, парный интервал [-0.221, -0.129], эффект 0.174 бита; order 0 baseline даёт 5.058 против 6.364, uniform 6.000; маргинальная H 4.014 [3.885, 4.136] против 5.468 [5.402, 5.539] конфаундирована алфавитом и служит диагностикой. пассивная обучаемость даёт cycle 88/100 при L = 65 (длины партий cycle 58..155), bio 0/100 и random 0/100. детекция 8/10 отозвана: firmware det_fired 0/10 после 2010 ms, raw пересечения порога 2/10, а записанные 3/10 относятся к t0 = 1000 ms до стимула. seed xorshift64* восстанавливается по 3 портам в диапазоне 200001 кандидатов за under one second при знании кода; четыре структурных теста дают 0/20 каждый, blind seed recovery не реализована. тайминг режимонезависим на 100/100 сидах. реплей бит в бит подтверждён на 1 паре; все 300 журналов совпадают с манифестом, 1 из 300 регенерирован текущим бинарником. readout есть достаточное узкое место, вклад коннектома не проверен. новизна: не заявляется. обзоры метрик MTD существуют [cho et al., 2020; ## 1 введение

### 1.1 вопрос

детерминированный симулятор с сидом есть keyed deterministic generator: детерминированная функция ключа. ведёт ли она себя как ГПСЧ, есть эмпирический вопрос для заявленного атакующего (docs/RESEARCH_V2.md:5-6). вопрос, случайнее ли такое расписание сеяного генератора, выиграть нельзя: при алфавите 64 символа максимум энтропии равен log2(64) = 6 бит на ход, а one time pad достигает этой границы, а не превышает её [shannon, 1949, cited in docs/PLAN_V11.md:12-14]. ранний черновик утверждал, что one time pad превышает границу; это неверно и исправлено здесь.

полезный вопрос уже: при данном детерминированном генераторе и заявленном классе атакующего сколько наблюдений нужно атакующему и что артефакт действительно измеряет. работа отвечает на это для существующего артефакта и фиксирует, где ответ отрицателен.

### 1.2 границы и нецели

работа не является работой по безопасности. она не предлагает защиту, не измеряет стоимость атаки против сетевого противника и не сравнивает с криптографическим PRF. CSPRNG плечо не реализовано, baseline ChaCha20, HMAC-DRBG или рандомизация эфемерных портов не измерены; grep по дереву находит ChaCha только в планировочной заметке о стороннем KDF (docs/PLAN_V11.md:23). сеяное плечо здесь есть xorshift64*, не универсальный CSPRNG. площадка по безопасности должна отклонить эту работу по охвату. это сказано до ревьюера. чистая функция фиксированного ключа не может зависеть от наблюдений атакующего; PRNG с внешним входом может. связь расписания с атакой не измерялась (h13, docs/hypotheses.md:276-285).

работа предлагается как отчёт о методах и отрицательных результатах для воспроизводимой вычислительной нейронауки и оценки артефактов. положительное содержание: воспроизводимый артефакт, инструмент и опровержения.

### 1.3 вклад

1. детерминированный headless генератор расписания с побитовым реплеем, записанным бинарником, компилятором, флагами, файлом событий и манифестом (results/manifest.txt).
2. операционный инструмент обучаемости L с документированным несовпадением с прозаическим определением и отдельный конструкт n_obs_to_recover для восстановления сида (tools/learnability.py:53-108; реализован в tools/seed_recovery_attack.py).
3. held out анализ log-loss порядка 1 по поставленным журналам, вычисленный здесь, который заменяет насыщенный L как сравнительную метрику.
4. каталог опровержений с измерениями, которые их устанавливают: насыщение метрики, readout ранга 1, отказ политики сида, режимонезависимый тайминг и результат детектора, не выдерживающий проверки.
5. явные границы провенанса артефакта, включая несовпадение бинарника и commit между манифестом и журналами h9.

не заявляется: замкнутый контур коннектома, свойство безопасности, частота детекции, частота ложных тревог, coupling, внешняя валидация, валидированное число нейронов во время выполнения.

### 1.5 обзор близких работ

рандомизация эфемерных портов и опубликованные атаки. rfc 6056 [larsen, gont, 2011, recommendations for transport-protocol port randomization] ставит задачу в тех же терминах: если одна глобальная переменная хранит последний эфемерный порт, "the next ports chosen by the client are easy to predict". документ прямо говорит, что цель есть уменьшить вероятность угадывания, "rather than to actually produce mathematically random sequences of ephemeral ports". он перечисляет пять алгоритмов: simple port randomization, another simple port randomization, simple hash based port selection, double hash port selection и random increments; рекомендует весь диапазон от 1024 вверх и сообщает частоту коллизий не более 0.3% для всех алгоритмов. здесь важны два свойства. первое: режим отказа, который называет rfc, есть точно режим cycle, port_k = 40000 + ((k+1) mod 64) (src/motor.c:133), и атакующий с правилом delta достигает точности 0.90 после 2 ходов, 20 из 20 (results/schedule_attack/REPORT.md:27). второе: baseline rfc есть локальная политика выбора, а плечо cycle есть детерминированный счётчик без ключа вообще, поэтому результат cycle воспроизводит предупреждение rfc на другом субстрате; это не новое открытие.

рандомизация не закрывает поверхность атаки. man, zhou и qian [man, zhou, qian, 2021, dns cache poisoning attack: resurrections with side channels] показывают, что сетевые побочные каналы "can effectively derandomize the ephemeral port number" даже при рандомизированном порте. результат A2 есть тот же урок на уровне генератора: сид xorshift64* восстанавливается по 3 наблюдённым портам в диапазоне 200001 кандидатов, когда генератор известен (3.6, N2). работа не измеряет сетевой побочный канал; классы A5 и A6 не запускались. корректное сравнение: man et al. дерандомизируют рандомизированный порт через сеть, эта работа восстанавливает сеяный генератор через его выход, и ни одно не является доказательством о другом.

port hopping и модели успеха атакующего. port hopping есть ближайший опубликованный дизайн к движущемуся расписанию портов. lee и thing [lee, thing, 2004, port hopping for resilient networks] меняют "the UDP/TCP port number used by the server ... as a function of time and a shared secret between the server and the client", с теоретическим и эмпирическим исследованием против отказа в обслуживании; это расписание, зависящее от времени, с ключом, а плечо random в работе есть вырожденный случай с целым аргументом командной строки как ключом. самая сильная количественная предпосылка: luo, wang и cai [luo, wang, cai, 2014, effectiveness of port hopping as a moving target defense] вводят urn модель и "quantify the likelihood of attacker success in terms of the port pool size, number of probes, number of vulnerable services, and hopping frequency". это ближайший опубликованный конструкт к L: оба суть функции числа наблюдений, но luo et al. сообщают вероятность успеха, а эта работа сообщает первую длину префикса, на которой пересекается порог точности 0.9. L есть порог сложности выборки, не вероятность, и это сказано в обсуждении. два дальнейших источника ограничивают утверждение. hari и dohi [hari, dohi, 2010, sensitivity analysis of random port hopping] анализируют случайный port hopping "in terms of the communication success rate" и предлагают мелкозернистый вариант; стоимость защитника входит в их метрику, а эта работа не сообщает частоту успеха легитимного трафика для атаки на расписание, только число ходов и точность предсказания, поэтому член стоимости отсутствует. jafarian, al-shaer и duan [jafarian, al-shaer, duan, 2012, openflow random host mutation; jafarian, al-shaer, duan, 2015, an effective address mutation approach for disrupting reconnaissance attacks] трактуют мутацию адресов и портов как контрмеру против разведки и утверждают, что "network reconnaissance of addresses and ports is prerequisite to a vast majority of cyber attacks"; их переменные дизайна: непредсказуемость, частота мутации и адаптация к противнику. в этом артефакте частота мутации фиксирована рефлексом и детектором и режимонезависима (3.2), а readout имеет ранг 1 (2.2), поэтому обе переменные дизайна ограничены до того, как входит коннектом.

обучение расписанию MTD. опубликованная работа об обучении расписанию MTD мала, но пряма. moghaddam et al. [moghaddam, yang, thapa, camtepe, kim, 2024, mtd in plain sight: hiding network behavior in moving target defenses] показывают, что "an attacker who knows the MTD window can greatly increase their attack success rate", что триггер MTD утекает достаточно трафика для обнаружения и что имитирующие триггер события могут обмануть атакующего и увести его в неверное окно. результат f6 в этой работе есть утечка окна такого рода: моменты ходов одинаковы во всех режимах, поэтому наблюдатель узнаёт, когда может произойти следующий ход, не узнавая порт (docs/RESEARCH_V2.md:102-108). отзыв детектора есть второй пример: каждый журнал в наборе детектора записывает det_fired при t = 1000 ms, до вспышки при t = 2000 ms (3.5), поэтому триггер детектора есть фиксированная наблюдаемая. опубликованный прецедент машинного обучения: mani et al. [mani, haliem, bhargava et al., 2023, machine learning based resilience testing of an address randomization cyber defense] проверяют supervised обнаружение смен адресов и LSTM предиктор будущих адресов для рандомизированного назначения адресов в военной последовательной шине и сообщают, что LSTM "was able to predict the future addresses with varied effectiveness based on MTD algorithm's settings". это более сильный атакующий, чем модель порядка 1 в A1. held out точность 0.0712 [0.0540, 0.0901] для bio против 0.0100 [0.0047, 0.0158] для random (3.4) есть измеренная точность этого атакующего; более сильный атакующий мог бы показать больше, поэтому это не верхняя граница для класса "обучающийся атакующий". ревьюер запросит LSTM плечо или явное утверждение, что класс атакующего слаб.

метрики MTD и энтропийная гипотеза. существуют три обзора метрик и оценки MTD: cho et al. [cho, sharma, alavizadeh et al., 2020, toward proactive, adaptive defense: a survey on moving target defense] покрывают "metrics, evaluation methods, and application domains"; sengupta et al. [sengupta, chowdhary, sabur et al., 2020, a survey of moving target defenses for network security] классифицируют MTD по "qualitative and quantitative metrics" и называют конфиденциальность, целостность, доступность, представление атаки, влияние на QoS и модели угроз как количественные оси; cai et al. [cai, wang, hu, wang, 2016, moving target defense: state of the art and characteristics] покрывают "MTD theory, MTD strategy, and MTD evaluation". их таблицы метрик не прочитаны, проверены только аннотации, поэтому проверенного количественного обзора в этой работе нет, конкретные списки метрик не пересказываются, а новизна L не заявляется. центральная теоретическая цель есть энтропийная гипотеза MTD. zhuang, deloach и ou [zhuang, deloach, ou, 2014, towards a theory of moving target defense] формализуют её как "the greater the entropy of the system's configuration, the more effective the MTD system" и отмечают отсутствие стандартного определения метрики до их предложения. результат N8 есть прямой контрпример на конкретном артефакте: cycle имеет plug-in маргинальную H 5.941 [5.931, 5.952] бита, однако атакующему с правилом delta нужно 2 хода, а марковскому атакующему 62 хода в 14/20 журналов и больше 99 в 6/20 (3.4, 3.6). энтропия конфигурации не упорядочивает усилие атакующего. это сильнейший теоретический вклад, доступный работе. альтернатива есть семейство вероятностных метрик: carroll et al. [carroll, crouse, fulp, berenhaut, 2014, analysis of network address shuffling as a moving target defense] количественно оценивают "the probability of attacker success in terms of network size, quantity of addresses scanned, quantity of vulnerable systems, and the frequency of shuffling". L содержит число наблюдений и класс атакующего, но не уязвимую популяцию и не частоту сканирования, поэтому L не заменяет эту метрику; это другой срез той же задачи, и обсуждение говорит, какой срез измеряется, а какой нет. статус новизны L: UNCERTAIN, опубликованной работы, использующей первую длину префикса при пороге точности 0.9 как метрику MTD, не найдено; отсутствие в прочитанных источниках не есть доказательство отсутствия, корректная формулировка: "идентичная метрика в проверенных источниках не найдена".

сеяные генераторы с линейным или почти линейным состоянием восстанавливаются: xorshift (Marsaglia 2003), xorshift* и xoshiro (Vigna 2014, 2016), оба названы в docs/RESEARCH_V2.md:151-152 и внесены в paper/REFERENCES.md. оценивание min entropy физических источников шума стандартизовано в NIST SP 800-90B (docs/RESEARCH_V2.md:153); оно оценивает источник и не является свидетельством об этом расписании.

нейронаучные источники и предсказуемость. источники, которые называет движок: Yemini et al. 2013, Pierce-Shimomura et al. 1999, Kato et al. 2015 и Tsodyks and Markram 1997 (README.md, раздел цитирования); модель не воспроизводит измеренную поведенческую величину ни из одного из них, поэтому это провенанс, не валидация. предсказуемость как междисциплинарное понятие обсуждают Boffetta, Cencini, Falcioni и Vulpiani 2001, а сходимость permutation entropy при шуме Amigó, Dale и Tempesta 2020 и Chen и Sato 2024, как записано в docs/RESEARCH_V2.md:137-145; записи 14 и 15 в paper/REFERENCES.md помечены как не перепроверенные. 14 записей MTD из docs/RESEARCH_V3.md, а также Boffetta 2001 и Vigna 2016 внесены в paper/REFERENCES.md в ревизии 5.

## 2 методы

### 2.1 движок и проводка

движок есть вендоренная сокращённая модель petri v1.2, commit 42d5062, из upstream репозитория, записанного в src/petri/VENDOR.md (также docs/hypotheses.md:224, docs/STATE.md:10). это не модель нейрона на проводимостях: neuron_act есть одна сигмоида мембранного потенциала (src/petri/neuron.c:7-10), потенциально зависимых каналов нет, тело состоит из 24 сегментов. корректная метка: сокращённая модель с graded potential, не биофизический симулятор. bridge_init поднимает noise_scale до 1.0 во время выполнения (src/bridge.c:22-29), потому что wild type загрузчик оставляет его нулевым; это runtime правка, не свойство CSV, и она входит в методы.

лист проводки src/petri/data/varshney_full.csv содержит 6417 строк данных плюс заголовок, 6418 строк по wc -l, по типам S, SP, R, RP, EJ и NMJ (посчитано здесь). 6417 это счёт строк, не счёт синапсов. загрузчик отбрасывает все 153 строки NMJ, сводит строки EJ к 517 уникальным ненаправленным парам и размещает химические строки отправителя (S, SP) и получателя (R, RP); итоговый граф в этой сборке объединяет химические строки с 517 парами gap (правила загрузчика src/petri/connectome.c:360-400). после отбрасывания NMJ загрузчик даёт 279 узлов (пересчитано здесь); 281 это число различных токенов в сыром файле, лишние два токена встречаются только в строках NMJ. VC6 есть реальный нейрон, который встречается только в строке NMJ на строке 6205 и теряется вместе со 153 строками NMJ; в загруженном графе его нет. runtime c->n_neurons печатается src/petri/sim.c:67-70, но демон принудительно ставит opts.quiet = 1 в src/bridge.c:17, поэтому строка подавлена; 279 это пересчёт правила загрузчика, не runtime лог.

два дефекта модели важны для интерпретации. первый: знак синапса отсутствует в CSV; файл имеет четыре колонки и не имеет sign колонки, поэтому химическая строка тормозная только если имя пресинаптической клетки имеет один из семи префиксов GABA (src/petri/connectome.c:22-24, 45-48, 386-397); по этому правилу тормозными являются 203 из 5233 химических строк, 3.9% (посчитано здесь). правило префикса есть эффективное правило знака, остальные строки по умолчанию возбуждающие. второй: строки EJ дедуплицируются в одно направленное ребро на пару, а синаптический шаг добавляет pn->i_gap += g*(pre->v - pn->v) только постсинаптической клетке (src/petri/sim.c:377-380), поэтому 517 gap контактов это односторонние проводники, не шунтирующие электрические синапсы. оба свойства относятся к модели, не к данным; любой вывод, зависящий от баланса торможения или связи gap, чувствителен к ним.

### 2.2 readout и вопрос политики

назначение bio есть index = floor(64 * mean(act_ava, act_avb, ash_trace, ser, oct, dop)), реализовано в src/bridge.c:101-107. это написанный вручную линейный функционал ранга 1. четыре из шести членов не являются независимыми наблюдаемыми коннектома в том смысле, который подразумевал ранний черновик:

- ash_trace есть след ноцицептора, то есть сам вход событий.
- ser и oct обновляются в src/session.c:344-363 как ser += K_SER * share * dt и oct += K_OCT * density * dt, где density это частота событий вспышки, а share доля легитимного трафика; обе константы в src/config.h:118 и 123.
- dop есть скаляр модулятора из sim->mod.dop, не активация нейрона.
- ava насыщена: около 1 с малой дисперсией на 60000 строках журнала bio сида 1001 (архив журналов, results/BULK_DATA.md; посчитано здесь).

на 60000 строках bio сида 1001 корреляция Пирсона метки порта с каждым членом равна 0.578 для dop, 0.465 для ash_trace, 0.154 для ser, -0.133 для oct, 0.065 для avb и 0.029 для ava. диапазоны: ava mean 0.993, sd 0.015, min 0.701; avb mean 0.792, sd 0.335; dop mean 0.030. метка поэтому сильнее связана с двумя не нейронными членами dop и ash_trace, чем с любой командной клеткой. верхний порт в сиде 1001 есть 40031 с 8705 из 60000 тиков, доля 0.145; pooled n = 20 top-1 доля ходов 0.139 [0.124, 0.156], два верхних порта несут 23.4% ходов (results/schedule_attack/REPORT.md; посчитано здесь). масса индекса концентрирована, и из 279 клеток до порта доходят только две командные клетки AVA и AVB и сенсорный след; AVA почти постоянна, а AVB слабо коррелирована, поэтому эффективный вклад нейронов мал.

поэтому не заявляется, что политики нет. она есть: фиксированный линейный readout плюс экзогенная инъекция модулятора из двух членов, ведомая счётчиками событий. отсутствует целевое состояние, целевой вектор или обученная политика. корректная формулировка: "метка порта есть фиксированный написанный вручную функционал состояния движка и счётчиков событий", а не "карта есть смоделированная нервная система".

### 2.3 тайминг: рефлекс, детектор и режимонезависимость

момент хода задают рефлекс и детектор, не режим назначения. motor_move_to вызывается только при cause != 0 (src/session.c:385-392), а cause ставит детектор (CAUSE_DET) или рефлекс реверса движка (CAUSE_ENDO). режим выбирает аргумент motor_move_to, не тик. это измерено в 3.2: строки хода с флагом причины имеют одинаковые метки времени в bio, cycle и random на 100 из 100 сидов, а таблица шести сидов там есть выборка.

следовательно, утверждение h2, что "коннектом решает только тайминг" (docs/hypotheses.md:205), неверно и на сборке v1.2. на v1.2 тайминг режимонезависим, а в режиме bio коннектом решает метку. h2 измерялась на старом ядре и на устаревшем пути счётчика; охват ограничен.

### 2.4 режимы расписания и умолчания

режим назначения по умолчанию DEST_CYCLE = 0 (src/config.h:31), cfg.seed по умолчанию 1 (src/proteusd.c:38). режимы:

- cycle: port = PORT_BASE + (binds mod 64) (src/motor.c:133), счётчик.
- bio: motor_move_to(&mo, bridge_dest_index(&br)) (src/session.c:388).
- random: motor_next_random, xorshift64* с сидом из целого аргумента командной строки (src/motor.c:18-30, 182).

live режим строит фиксированную перестановку из того же сида и применяет её (src/motor.c:98, 162). перестановка не секрет: сид это целое аргумента командной строки со значением по умолчанию 1, и перестановка выводится из него. слово "секретная" из раннего черновика удалено. headless режим перестановку не применяет (src/motor.c:155 вызывает headless_bind, который игнорирует m->perm). каждое измерение в работе headless.

### 2.5 метрика L и n_obs_to_recover

L есть операционное определение в tools/learnability.py:53-108. для последовательности портов s при каждой длине префикса o из {10, 15, ..., min(500, |s| - 10)} предиктор обучается на s[:o] по маргинальным частотам и переходам первого порядка и оценивается на s[o:o+20]. L это первое o, при котором точность не ниже 0.9; если такого нет, функция возвращает max_obs = 500. окно s[o:o+20] обрезается концом партии, поэтому префиксы у хвоста оцениваются менее чем на 20 ходах. L есть порог точности на окне 20 ходов, квантованный шагом 5, цензурированный длиной партии, а не вероятность следующего действия. прозаическое определение в docs/CLOSE.md:26-28 (прежний README до ревизии 3 нёс ту же формулировку) не совпадает с кодом; код является определением здесь.

тот же инструмент содержит заглушки active и reconstruction наблюдателей (compute_L_active возвращает max(10, passive/2.5), compute_L_reconstruction возвращает min(passive*3, 500), tools/learnability.py:110-130). используется только compute_L_passive. путь агрегации инструмента применяет df['port'].diff() != 0, что исключает начальный порт (tools/learnability.py:183); таблица h9 и пересчёт здесь включают его. это меняет сообщённые счётчики; конвенция указывается в каждой таблице.

для восстановления сида используется n_obs_to_recover: число наблюдённых портов, после которого множество кандидатов сида имеет размер один. он реализован как n_obs_to_recover в tools/seed_recovery_attack.py и запускается флагом --nobs; это другой конструкт, не L, и он никогда не помещается в столбец L.

### 2.6 held out log-loss

предрегистрированной сравнительной метрикой был held out log-loss в битах на ход, с L только как нижней границей (docs/RESEARCH_V2.md:196-199). он вычисляется здесь по 20 поставленным журналам на семейство (сиды 1001..1010 и 1091..1100). для каждого журнала первые 60% последовательности портов это обучение, последние 40% тест, модель порядка 1 с лапласовым сглаживанием alpha = 0.5 по алфавиту 64 символа, оценка есть средняя отрицательная log2 вероятность тестовых символов. интервал для разности bio минус random есть bootstrap 95% по 20 журналам, 4000 resamples парных разностей. order 0 held out референс с тем же разбиением и сглаживанием даёт 5.058 для bio, 6.306 для cycle и 6.364 для random; uniform по 64 символам есть 6.000. значения H_pi в 3.4 суть plug-in маргинальные энтропии, не order 0 held out оценки. оценщик и alpha выбраны после просмотра данных; анализ exploratory и не предрегистрирован. разбиение 60/40 не контролирует нестационарность (transient ava и вспышку ash); точность по квартилям времени не вычислялась.

### 2.7 статистические процедуры

- schedule attack (n = 20 журналов на семейство): bootstrap 95%, 4000 resamples (results/schedule_attack/REPORT.md:3-5).
- пропорции: Wilson и Clopper-Pearson называются там, где используются. для 8/10 Wilson [0.490, 0.943], Clopper-Pearson [0.444, 0.975], пересчитано здесь. для 3/10 Wilson [0.108, 0.603].
- счётчики: к числу тревог детектора не прикрепляется интервал Poisson. события не независимы: каждый тихий журнал содержит детерминированный det_fired при t = 1000 ms (3.5).
- ходы на партию: среднее, выборочное sd, двусторонний 95% t интервал. предрегистрированная проверка полосы есть сравнение с порогом, не статистический тест.
- цензурирование: сообщается доля партий, достигших 0.9, и распределение длины партии; сентинел 500 не является оценкой.
- множественность: family wise alpha 0.05 с 0.0083 на гипотезу зарегистрирован для блока h1..h6 (docs/hypotheses.md:150-201 и 242-251). измерения h9, h10 и schedule attack не корректировались; они exploratory и помечены так.

### 3.3 h9: пассивная обучаемость

дизайн: 300 партий, 100 сидов (1001..1100) умножить на 3 режима, один файл событий, один бинарник (docs/hypotheses_results.md:19-23). одна партия на сид. пересчитано здесь из results/journals_v12 с tools/learnability.py, включая начальный порт.

| семейство | партии, достигшие 0.9 | медиана L | длина партии, ходы (конвенция таблицы, начальный порт исключён) |
|---|---|---|---|
| bio | 0/100 | 500 (сентинел) | 44..141 |
| random | 0/100 | 500 (сентинел) | 57..154 |
| cycle | 88/100 | 65 | 58..155 |

конвенция столбца длины: results/paper_stats.py исключает начальный порт, а пересчёт L в 5.2 включает начальный порт. поэтому минимум cycle 58 в таблице есть промах, а в конвенции L ему соответствует 59; порог 76 относится к последовательности с начальным портом. две шкалы согласованы, но смешивать их нельзя.

зарегистрированный критерий 1, "bio L >= 500 в >= 95%", тавтологичен: инструмент ставит ровно 500, когда 0.9 не достигнута и когда в партии меньше 20 ходов (tools/learnability.py:57-58, 108). он заменён долей достигших 0.9 и кривой выживаемости по длине партии. сентинел 500 возвращён для 212 из 300 партий; потолок никогда не оценивался, а самая длинная партия есть 155 ходов в конвенции таблицы и 156 в конвенции с начальным портом. инструмент оценивает префиксы шагом 5 до |s| - 10 исключительно (tools/learnability.py), поэтому наибольший оценённый префикс для партии 156 ходов равен 145; 145 есть практическая граница для самой длинной партии с начальным портом, а 140 относится только к конвенции таблицы 155 ходов.

критерий 2 провален как зарегистрирован: 88/100, не 95%. все 12 промахов имеют длину партии 59..75 в конвенции L с начальным портом; все попадания не короче 76. пересечение на 65 лежит за пределами данных для партии короче 76, поэтому это цензурирование, не изменение расписания. критерий 3 провален как зарегистрирован: readout bio возвращает тот же порт на последовательных ходах, поэтому счёт смены порта недооценивает моторные события. пересчитано по 100 журналам bio: 1517 из 10048 ходов с флагом причины не сменили порт, 15.1%. docs/hypotheses_results.md:44 фиксирует 15.1%; других значений no-op в текст не входит.

значения Cohen d = 3.81 и p = 6.6e-21 не публикуются. docs/hypotheses_results.md:31 относит их к паре bio против cycle; cycle не постоянен на сентинеле 500 (88/100 при L = 65 и 12/100 на 500), поэтому причина отказа не постоянство обоих векторов, а цензурирование L длиной партии и невозможность оценить эффект расписания. "bio и random неразличимы" заменено на "оба не достигли 0.9, и тест невозможен при таких длинах партий". после замены критерия и провала критериев h9 exploratory. метка CONFIRMED в docs/hypotheses_results.md:19 в работу не переносится.

H_pi есть plug-in маргинальная энтропия с поправкой Миллера-Мадоу; log-loss есть held out cross entropy порядка 1 с лапласовым сглаживанием add 1 по алфавиту 64 символа. plug-in оценка энтропии смещена вниз, поправка Миллера-Мадоу добавляет (k-1)/(2 n ln 2); при n = 81 и k = 64 поправка 0.56 бита даёт для cycle 6.481, что выше потолка 6 бит. это диагностика выхода за область применимости, а не оценка энтропии: исправленные значения не публикуются как истина, для защитимой оценки нужны NSB или Chao-Shen, либо хотя бы 30 сидов. H_pi не есть held out log-loss порядка 0 по тому же разбиению и сглаживанию, но order 0 held out референс с тем же разбиением и сглаживанием даёт 5.058 для bio, 6.306 для cycle и 6.364 для random; uniform есть 6.000. столбец log-loss n = 1 сравнивает плечи только между собой, а не с H_pi.

таблица поддерживает четыре качественных вывода. плечо bio ранга 1: 16 различных портов из алфавита 64, маргинальная H 3.672 бита против 5.920 у cycle. cycle самое предсказуемое плечо на порядке 1 в этом сиде, что согласуется с точным счётчиком порта (структурные атаки ниже). random ниже равномерного референса по held out точности (0.000 против 0.0156), его маргинальная H 5.290 бита. ниже случайного уровня есть артефакт разбиения, не структура: add 1 сглаживание при разбиении 60/40 последовательности 80 ходов даёт невиданным тестовым символам меньшую массу, чем uniform, поэтому модель порядка 1, обученная на разреженном префиксе, проигрывает uniform на хвосте. согласованного baseline по алфавиту и длине нет; тот же артефакт даёт значение n = 20 0.0100 [0.0047, 0.0158] против uniform 0.0156 (results/schedule_attack/REPORT.md). все три dwell ряда передисперсны: коэффициент вариации 1.18..1.30.

сырой дефицит H, о котором сообщал ранний черновик, был артефактом меньшего алфавита readout bio, а не свойством расписания. H(port) здесь не публикуется как энтропия расписания (docs/RESEARCH_V2.md:89-94).

значения пересчёта n = 20 в results/schedule_attack/REPORT.md и повторены здесь: маргинальная H 4.014 бита [3.885, 4.136] у bio против 5.468 [5.402, 5.539] у random, только диагностика, потому что H конфаундирована размером алфавита; held out точность порядка 1 0.0712 [0.0540, 0.0901] у bio против 0.0100 [0.0047, 0.0158] у random, uniform 0.0156; перевес bio над uniform в основном сжатие алфавита (4.6x сырой против 1.5x по виденному алфавиту). парная разность точности равна 0.0612 с bootstrap 95% интервалом [0.0407, 0.0832], парная разность H равна [-1.519, -1.321]. log-loss порядка 1 по рецепту 2.6 воспроизводится командой 5.2 на поставленных журналах: 5.851 для bio, 4.869 для cycle и 6.025 для random, парный bootstrap 95% интервал разности bio минус random [-0.221, -0.129], эффект 0.174 бита (4000 resamples; посчитано здесь, docs/RESEARCH_V3.md). order 0 held out baseline с тем же разбиением и сглаживанием даёт 5.058 для bio и 6.364 для random, uniform 6.000. исходный конвейер /tmp не поставляется; эти точечные значения и интервалы пересчитаны здесь. сравнение log-loss несёт направление; сравнения accuracy и H exploratory и конфаундированы, первое сглаживанием, второе размером алфавита. средние ходы 87.2 [77.9, 97.4], 99.4 [89.5, 110.2], 98.9 [89.2, 109.6]; различных портов у bio 21.7 [19.8, 23.5] против 50.7 [48.4, 53.1] у random; доля двух верхних портов у bio 23.4%; первый ход bio есть 40032 в 20/20 журналах, он лежит в 60% обучающего префикса, не в held out 40% хвосте, поэтому не даёт held out попадания; порядок 2 добавляет к порядку 1 +0.0056 с интервалом [0.0000, 0.0150], интервал включает ноль на конце, поэтому прирост не отличим от нуля и точечная оценка не называется приростом. предрегистрированное сравнение non-inferiority сохранено качественно: bio предсказуемее плеча random, значит bio не non-inferior. это согласуется с readout ранга 1. сравнение exploratory: разбиение, сглаживание и alpha выбраны после данных, n = 20 журналов.

структурные атаки (REPORT §4): cycle точен 20/20 с port_k = 40000 + ((k+1) mod 64) и идеален для атакующего с правилом delta; random не объясняется аффинным LCG по модулю 64 (0/20), не объясняется аффинным отображением GF(2) на 6 битах (0/20) и не объясняется восстановлением состояния xorshift64* по младшим 6 битам выхода в проверенных конвенциях (0/20, синтетический положительный контроль 20/20); bio не LCG (0/20). четыре проваленных теста суть random affine LCG, random GF(2) affine map, random xorshift64* state recovery и bio LCG check, 0/20 каждый; cycle есть положительный контроль 20/20. blind seed-recovery атака не реализована. корректное резюме: "ни один из четырёх тестов не различил", а не "random согласован с равномерным на всех наблюдаемых уровнях". четыре теста не исчерпывают криптоанализ усечённого выхода xorshift, и проекция на 6 бит имеет структуру, которую мог бы использовать более широкий тест. анализ мощности не проводился, поэтому 0/20 есть отсутствие доказательства при заявленном наборе тестов.

детали утечки (REPORT §5): bio имеет детерминированный первый ход (40032 в 20/20), небольшой набор любимых портов и не достигает 0.90 за 600 s (0/20). cycle полностью предсказуем. random утечки не обнаружено; оценка около 303 ходов для перечисления всех 64 портов есть экстраполяция за окно и помечена как таковая.

|---|---|---|---|

интервалы между ходами без памяти во всех семействах: Ljung-Box p > 0.26, ACF лага 1 около 0. CV около 1.3 означает тяжёлый хвост, не периодичность. автокорреляция порта у bio есть возврат к любимым портам, не период; мощность cycle есть монотонный тренд, не рекуррентность.

### 3.5 детектор: записанные 8/10 не устанавливают детекцию вспышки

этот раздел отзывает результат детекции раннего черновика.

файл событий начинается с 2000,burst,1.0 (tests/fixtures/burst.csv:3), и след ash в журналах прыгает при t = 2010 ms. каждый из 10 журналов вспышки и каждый из 10 тихих журналов записывает событие det_fired (код события 4) при t = 1000 ms и ещё одно в фиксированное более позднее время (посчитано здесь). offline инструмент калибровки берёт t0 как первую строку с event in (1, 2, 4) (tools/calibrate_detector.py:56-60); поскольку событие 4 предшествует событию 1 в каждом журнале, t0 равен 1000 ms, а не вспышке при 2010 ms. его критерий "в окне" поэтому вычисляется до стимула.

следствия:

- в окне 3 s после события вспышки (первый ответ ash при 2010 ms) 0 из 10 журналов записывают firmware det_fired. три журнала срабатывают значительно позже (сиды 108, 104, 101), вне любого окна ответа на вспышку. первое пересечение raw det_score выше 50 в сидах 105 и 107 происходит при 850 ms и 800 ms, до firmware события det_fired при 1000 ms, поэтому offline state machine отсчитывает 10 s cooldown оттуда, а не от события 1000 ms. raw пересечения на уровне 50 и выше после 2010 ms есть в 2 из 10 журналов (34 отсчёта в сиде 105, 97 в сиде 107), но они попадают в этот ранний cooldown. firmware событие 1000 ms и offline state machine по raw score это разные механизмы, и каждое предложение ниже называет, какое из них используется.
- "3/10 в окне" есть артефакт t0 = 1000: сиды 102, 106 и 109 пересекают порог ровно при 1000 ms, за секунду до стимула.
- "8/10 максимум где угодно" считает предстимульные максимумы: во всех 10 журналах максимум det_score приходится на 1020..1030 ms, до вспышки. число отозвано как частота детекции.
- два журнала записывают det_fired ниже замороженного порога: det_burst_103 и det_burst_110 (их максимумы тоже ниже). либо прогон использовал меньший порог, либо столбец det_score не есть статистика, породившая событие. в обоих случаях утверждение "порог 50.0 заморожен до измерения стороны детекции" не поддерживается артефактами.
- счёт ложных тревог не есть счёт независимых тревог. все 10 тихих журналов делят детерминированные события при 1000 ms и фиксированное более позднее время; offline реплей score >= 50 насчитывает 8 пересечений всего. интервал Poisson на 8 предполагает независимость и недействителен. частота ложных тревог не заявляется.
- калибровка и оценка используют одни сиды (101..110); отложенный сид не запускался (docs/hypotheses_results.md:4-5).
- калибровочная сетка поставленного инструмента на сидах 101..110 даёт счётчики ложных тревог за 6000 s: 30:25, 40:16, 45:12, 50:8, 60:1, 70:0. запись 55:3 в docs/hypotheses_results.md:56 есть docs record и не воспроизводится поставленным инструментом. это счётчики, интервал не прилагается.

по поставленным артефактам неизвестно, реагирует ли детектор на вспышку вообще. корректный статус: "не установлено", не "8/10".

частота ходов в тишине остаётся измерением: среднее 97.5 ходов за 600 s, выборочное sd 24.9, 95% t интервал [79.7, 115.3], диапазон [62, 152], n = 10 (пересчитано из results/cal_v12/fa_101.csv до fa_110.csv). предрегистрированная полоса была [100, 300], скопированная из ссылки старого движка 187..214 ходов за 600 s (docs/hypotheses.md:234-235), не из поведения животного. среднее ниже полосы, интервал перекрывает 100; это записанный промах, не статистическое отклонение. поскольку тайминг режимонезависим (3.2), это число описывает часы рефлекса и детектора, не свойство коннектома.

### 3.6 отрицательные результаты

- N1, энтропийного превосходства нет. потолок алфавита 6 бит на ход. раннее утверждение о дефиците битов было артефактом алфавита (3.4); нормированные значения энтропии не определены и не приводятся, поэтому фраза о близости нормированной энтропии к потолку удалена.
- N2, у плеча xorshift64* сломана политика сида. DEST_RANDOM есть xorshift64* с сидом из целого аргумента командной строки, по умолчанию 1. реплей по сидам 0..200000, 200001 кандидат, оставляет 3177 кандидатов после 1 наблюдённого порта, 52 после 2 и 1 (сид 1001) после 3; восстановленный сид воспроизводит все 80 ходов, запуск занимает under one second на хосте ревью. это диапазон 200001 кандидатов со знанием исходников, не полный энтропийный взлом; стоимость полного энтропийного сида не измерялась (docs/RESEARCH_V2.md:65-69). результат 0/20 есть четыре структурных теста, 0/20 каждый; blind seed-recovery атака не реализована. корректное утверждение: "политика сида сломана", не "генератор сломан".
- N3, readout bio ранга 1. он даёт 16 различных портов в разведке n = 1 и 21.7 [19.8, 23.5] в пересчёте n = 20 против 50.7 [48.4, 53.1] у random; наблюдаемое число различных портов есть 21.7, структурная граница есть 64. более низкая маргинальная H у bio (4.014 против 5.468 бита) ожидаема из меньшего эффективного алфавита и служит диагностикой, не независимым доказательством. доказательство несёт held out точность порядка 1 0.0712, измеренная для этого атакующего, против 0.0100, с оговоркой 4.6x сырой перевес и 1.5x по виденному алфавиту (3.4). n = 20, results/schedule_attack/REPORT.md: точность порядка 1 0.0712 [0.0540, 0.0901] против 0.0100 [0.0047, 0.0158], uniform 0.0156, парный интервал [0.0407, 0.0832]. значения n = 1 произведены tools/paper_stats.py. readout есть достаточное узкое место; вклад коннектома не проверен, потому что topology null и абляция не запускались (4.2).
- N4, устаревший путь счётчика не есть расписание. port = PORT_BASE + binds % 64 (src/motor.c:133) есть режим по умолчанию (DEST_CYCLE = 0, src/config.h:31); на сидах 1001, 1002, 1050 и 1100 старое ядро дало 100.0% восходящий цикл 208..210 ходов и L = 65.0 со std 0 (docs/hypotheses.md:202-211). это старое ядро и режим cycle; в режиме bio сборки v1.2 метка приходит из readout. вывод ограничен соответственно.
- N5, фиксированная перестановка ничего не даёт и ломает журнал. биекция выходного алфавита поглощается обучающимся, который видит только перенумерованную последовательность и не имеет априорного распределения меток; это измерено на n = 1, секретная перестановка не тестировалась (F3). headless игнорирует перестановку, а live применяет её (src/motor.c:155, 162), поэтому измерения по журналу не описывают живой поток (F2) (docs/RESEARCH_V2.md:74-87).
- N6, промах частоты ходов. среднее 97.5, 95% доверительный интервал [79.7, 115.3], диапазон [62, 152], n = 10, ниже полосы старого движка по среднему (3.5).
- N7, критерии 2 и 3 h9 провалены. 88/100 при L = 65 вместо 95%; 15.1% ходов bio суть no-op.
- N8, маргинальная H не есть непредсказуемость. cycle имеет почти максимальную plug-in маргинальную H 5.941 [5.931, 5.952], однако атакующему с правилом delta нужно 2 хода, а марковскому атакующему 62 хода в 14/20 журналов и больше 99 в 6/20; это разные правила атакующего, не один L.
- N9, тайминг режимонезависим. одни и те же 82 (или 67, 76, 91, 140, 85) меток времени ходов возникают во всех трёх режимах (3.2). коннектом не задаёт тайминг; в режиме bio он задаёт только метку, функционал ранга 1 (2.2).

## обсуждение и заключение

работа даёт один отрицательный результат и один числовой инвентарь: расписание с меткой из readout коннектома не превосходит xorshift64* по order 1 log-loss, тайминг режимонезависим на 100/100 сидах, readout ранга 1, политика сида xorshift64* восстанавливается по 3 портам, детектор не устанавливает детекцию вспышки. ценность в воспроизводимом артефакте, инструменте L и каталоге опровержений, не в защитном свойстве.

сравнение имеет границы, которые нужно назвать до ревьюера. [carroll et al., 2014] и [luo, wang, cai, 2014] сообщают вероятность успеха атакующего при бюджете сканирования, эта работа сообщает длину префикса при пороге точности. [hari, dohi, 2010] включает частоту успеха легитимной связи, эта работа её не сообщает; член стоимости отсутствует. [mani et al., 2023] использует LSTM, эта работа использует марковскую модель порядка 1; 0.0712 против 0.0100 есть измеренная точность реализованного атакующего, более сильный атакующий мог бы показать больше, поэтому это не верхняя граница для класса обучающихся атакующих. [moghaddam et al., 2024] измеряет реальный сетевой триггер, эта работа измеряет инъекцию событий из CSV. это разные срезы, и их нельзя переносить друг на друга.

сравнение с поведением животного остаётся разведкой n = 1 и входит только сжатой оговоркой. 6.90..8.10 ходов в минуту в симуляторе против 1.29 спонтанных реверсов в минуту [nagele, metz, crowder, 2004] и среднего интервала 16.3 s [stephens et al., 2011]; отношение равно 5.4..6.3 для частоты реверсов и 1.88..2.22 для интервала 16.3 s, ранний текст смешивал их в один диапазон 1.88..6.3. сравнение опирается на две проекции без источника: одна смена порта равна одному реверсу, одна секунда модели равна одной секунде животного; скорость тела в журнале не логируется, поэтому даже "тело замедляется" проверить по поставленным артефактам нельзя. это проверка порядка величины, не валидация модели.

программа будущих проверок, без данных: C1, схема bio не проигрывает ГПСЧ, метрика held out log-loss, margin 0.10 бит на ход, n = 30 партий, фальсификатор разрыв больше 0.10 в пользу ГПСЧ; C2, проба атакующего меняет расписание, KL не меньше 0.1 бита, bootstrap 95% без нуля, n = 30; C3, статистика дрейфует, падение held out точности не меньше 0.05 абсолютных от Q1 к Q4, n = 30; C4, развёртывание невоспроизводимо, атака 3 портов проваливается, аудит проходит. h12 требует H(next|hist) не меньше 5.0 бит на ход и held out точность порядка 1 не выше 0.05 в не менее 27 из 30 сидов; h13 требует KL не меньше 0.1 бита с интервалом без нуля; h14 требует падения не меньше 0.05 абсолютных; h15 требует TOST с margin 0.01. ни одна из этих проверок не запускалась, и никакие числа по ним не заявляются.

заключение: работа не устанавливает свойства безопасности, не измеряет частоту детекции, не измеряет частоту ложных тревог и не показывает замкнутого контура. она устанавливает, что в текущем артефакте метка расписания предсказуемее xorshift64* по order 1 log-loss, тайминг не зависит от режима на 100/100 сидах, readout имеет ранг 1, политика сида xorshift64* сломана, а детектор не устанавливает детекцию вспышки. эти результаты отрицательны, воспроизводимы и составляют ценность артефакта.

## 4 ограничения

### 4.1 что не заявляется

- свойство безопасности, сравнение с криптографическим baseline и преимущество над ChaCha20, HMAC-DRBG или обычной рандомизацией портов не заявляются. ни один baseline не реализован (grep по дереву; docs/PLAN_V11.md:23 упоминает ChaCha только в заметке о стороннем KDF).
- замкнутый контур не заявляется. тайминг режимонезависим (3.2), а readout включает след событий и два счётчика событий (2.2). readout есть достаточное узкое место; вклад коннектома не проверен, потому что topology null и абляция не запускались.
- частота детекции и частота ложных тревог не заявляются. записанные события предшествуют стимулу (3.5).
- coupling не заявляется. h13 никогда не запускалась (docs/hypotheses.md:276-285).
- внешняя валидация не заявляется. ни одна измеренная поведенческая величина из Yemini et al. 2013, Pierce-Shimomura et al. 1999, Kato et al. 2015 или Tsodyks and Markram 1997 не воспроизведена. сравнение частоты с опубликованными assay есть разведка n = 1 (results/behaviour_comparison.md): 6.90..8.10 ходов в минуту против 1.29 [nagele, metz, crowder, 2004] и 16.3 s [stephens et al., 2011]; отношение 5.4..6.3 для частоты реверсов и 1.88..2.22 для интервала 16.3 s. оно опирается на две проекции без источника и на n = 1 сид на режим; скорость и кривизна тела в журнале не логируются.
- развёртывание не заявляется. live и headless потоки расходятся.
- валидированное число нейронов во время выполнения не заявляется. 279 есть пересчёт правила загрузчика; строка лога подавлена.
- частота ходов, выведенная из животного, не заявляется. полоса [100, 300] пришла из старого движка.
- LSTM атакующий не заявляется. реализованный атакующий есть марковская модель порядка 1, слабее [mani et al., 2023]; 0.0712 есть измеренная точность этого атакующего, более сильный атакующий мог бы показать больше.

### 4.2 что не измерено и не запущено

- привилегированный bench: принуждение nftables в ядре, активная проба в netns, аудит gcore и негативный тест seccomp не запускались (docs/RELEASE_V1.md:5-7, docs/BENCH_PENDING.md). статус pending, не заявляется.
- отложенные сиды 2001..2100 не запускались ни для одного результата здесь (docs/hypotheses_results.md:4-5).
- h1..h4 и h6 не имеют вердиктов на текущем ядре (docs/hypotheses_results.md:64-70); h5 измерена на старом ядре и исключена (docs/hypotheses_results.md:7-17); h12..h15 не запускались (docs/hypotheses.md:266-305, поправка 306-316).
- бюджета активной пробы не существует. h13 не имеет данных и анализа мощности.
- сетевых измерений нет: вспышка есть инъекция событий из CSV, а сенсор, путь accept и классификатор payload не задействованы ни в одном измеренном прогоне. слово "scan" в реферате относится к виду события, не к трафику в сети.
- измерения нарушения или стоимости атаки нет. слушатель привязан только к loopback (bind_addr = 127.0.0.1, src/motor.c:16), окно есть 64 порта внутри 40000..40063 (src/config.h:17-18). окно 64 порта ограничивает blind скан 64 SYN; атакующий, знающий расписание, может сократить это до одного SYN на ход, поэтому предсказуемость меняет стоимость, а не возможность обнаружения сервиса. motor_move_to также двигает вперёд, когда порт занят (src/motor.c:163-175), поэтому локальный процесс может сдвинуть расписание.
- модели нулевой топологии нет. движок имеет реализацию перестановки рёбер (src/petri/sim.c:79-117), но не имеет флага CLI и перемешанного плеча ни в одном журнале, поэтому ни одно число здесь нельзя отнести к структуре коннектома, а не к случайной матрице смежности. readout есть достаточное узкое место; вклад коннектома не проверен.
- скрининга абляций и мутантных фенотипов нет, хотя движок содержит и то и другое (src/petri/sim.c:781-785, src/petri/mutants.c:16-98). это стандартная нейронаучная проверка, и она не запускалась.
- сравнения с внешним симулятором нет. порт на NEURON или Brian2 был бы другой моделью и не валидировал бы эту; решающие внешние проверки суть поведение животного, нулевая топология и фенотипы абляций.
- неполный прогон n = 30 не используется: он не завершён, и его числа не публикуются до завершения.

### 4.3 дефекты модели и артефакта

1. readout ранга 1 (src/bridge.c:101-107): наблюдаемое число различных портов 21.7 [19.8, 23.5] против структурной границы 64; масса индекса концентрирована в двух верхних портах (23.4% ходов).
2. написанная вручную политика модулятора: oct и ser инжектируются из плотности вспышки и доли легитимного трафика (src/session.c:344-363) и оба входят в readout. утверждение "слоя политики нет" ложно.
3. односторонние gap junctions: 517 уникальных пар EJ каждая инжектирует ток только в одну клетку (src/petri/sim.c:377-380).
4. знак по префиксу имени: 203 из 5233 химических строк, 3.9%, тормозные по правилу префикса; sign колонки в CSV нет, остальные по умолчанию возбуждающие. VC6 встречается только в строке NMJ и теряется, всего 153 строки NMJ. насыщение AVA может быть артефактом знака, а не свойством проводки; альтернатива не проверялась.
5. live и headless расходятся (src/motor.c:155, 162).
6. журналы h9 произведены cafd37d7 при 4c5eb5d, не бинарником манифеста 60b04860 при 91cabe5a; все 300 журналов совпадают с sha256 манифеста, 1 из 300 регенерирован текущим бинарником.
7. конвейер schedule attack не поставляется.
8. L не есть литературная величина и цензурирован длиной партии; active и reconstruction наблюдатели инструмента суть заглушки.
9. столбец события детектора и столбец det_score расходятся ниже порога (3.5).
10. данные ложных тревог, детекции и калибровки делят сиды 101..110; отложенной оценки нет.
11. поправки на множественность для exploratory метрик нет.
12. стоимость атаки на остаточный 64 битный сид не измерена.

### 4.4 программа исследований, только предложение

следующие проверки зарегистрированы в docs/hypotheses.md и docs/PLAN_V11.md, но не запускались; ни одно число по ним здесь не сообщается.

- C1 non-inferiority на held out log-loss против сеяного генератора при согласованных алфавите и атакующем, TOST margin 0.10 бита, n = 30 партий.
- C2 coupling: KL между распределениями следующего хода с активной пробой и без, порог 0.1 бита, bootstrap интервал без нуля, n = 30.
- C3 нестационарность: падение held out точности от первого к последнему квартилю, 0.05 абсолютных, n = 30.
- C4 невоспроизводимость развёртывания: свободный от сида ключ, MAC цепочка и commitment ключа; атака по 3 портам должна провалиться.
- h12 readout bandwidth, h13 active coupling, h14 nonstationarity и h15 permutation null зарегистрированы с критериями успеха и фальсификации и не имеют данных. h12 требует H(next|hist) не меньше 5.0 бит на ход и точность порядка 1 не выше 0.05 в не менее 27 из 30 сидов; h15 требует TOST с margin 0.01. h13 есть свойство, которого не может иметь чистая функция фиксированного ключа; она никогда не измерялась.

```bash
def ll1(s, alpha=0.5, k=64):
    cut = int(len(s) * 0.6); tr = s[:cut]; te = s[cut:]
    t = defaultdict(Counter); tot = Counter()
    for a, b in zip(tr[:-1], tr[1:]):
        t[a][b] += 1; tot[a] += 1
    prev = tr[-1]; loss = 0.0
    for x in te:
        loss -= math.log2((t[prev].get(x, 0) + alpha) / (tot[prev] + alpha * k))
        prev = x
    return loss / len(te)
for fam in ('bio', 'cycle', 'random'):
    fs = sorted(glob.glob(f'results/journals_v12/{fam}/*.csv'))
    want = {f'seed_{i}' for i in list(range(1001, 1011)) + list(range(1091, 1101))}
    vals = [ll1(seq(f)) for f in fs if any(w in f for w in want)]
    print(fam, len(vals), sum(vals) / len(vals))
PY
```
