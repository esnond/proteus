# detector score ROC, sandbox, 2026-10-29

method: tools/roc_sweep.sh, 4 runs with legit traffic only (400 sessions each) and 4
attack runs (window sweep, rate 50/s, 10 s). journals in /tmp/roc, not
committed. offline crossings of det_score approximate the live state
machine and are conservative (the live path has cooldown + refractory).

## live detector, operational numbers

- legit only: 0 bans in 1600 accepted sessions
- attack: 4 / 4 runs banned
- live threshold 30.0, frozen, not refit

the FP bound is not yet proven: with zero events the 95 percent upper
bound is 3/1600 = 18.8 per 10k sessions, above the 5 per 10k budget.
to claim the budget one needs about 6000 legit sessions; the bench script
defaults (10 runs x 60 s x 20/s = 12000) cover it.

## offline score sweep (conservative proxy)

    thr  fp_per_10k  detected
    30   50.0        4/4

reading: the score alone crosses the frozen threshold during legitimate
traffic (the state machine does not fire, hence 0 live bans), and the
crossings disappear with detection well above 30. the operating point
that reaches FP<=5 per 10k on the proxy sits above 34, where the attack
runs stop crossing. this is a real tension between FP budget and
detection at the score level and is published, not hidden.

## verdict

f1.4 as registered (a threshold with FP<=5/10k and useful detection) is
not supported by this sample. the live detector is 0/1600 FP and 4/4
detection at 30.0, but the bound needs 6000 sessions. next: run
`LEGIT_SECS=60 tools/roc_sweep.sh 10` on the bench and replace this file
with the version carrying full numbers.
