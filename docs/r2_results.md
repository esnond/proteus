# результаты р2

статус стадии на момент закрытия р2 в этой среде. гейты промта
оцениваются по фактической проверяемости, не по декларациям.

## что работает и проверено здесь

- сенсорный слой: non-blocking accept на движущемся слушателе,
  классификация пира по полезной нагрузке (сессия с данными против
  молчаливого скана), userspace-лист бана с ttl, детектор банит
  последнего сканера, сканы кормят ash-канал и счётчик плотности,
  сессии: канал легитимности. включается --listen, тестируется
  на loopback: сценарий "targeted scan then ban" в ci зелёный.
- генераторы трафика: scanner, legit_client, brute_forcer,
  mixed_traffic, csv-контракт rel_ms,event,ip,port,result.
- nftables-бэкенд: протокол nftables поверх libmnl без libnftnl
  (src/nft.c, константы из linux 6.6 uapi в src/nft_abi.h), атомарные
  батчи, таблица proteus, цепи prerouting/input, набор banned, правила
  drop/accept. код компилируется и линкуется, при отсутствии
  cap_net_admin бэкенд отказывает громко и демон работает на
  userspace-листе (--nft).
- seccomp: механизм установки (src/seccomp.c) и генератор белого списка
  из реального strace (tools/seccomp_gen.sh, make SECCOMP=1). в этой
  среде strace отсутствует, профиль не собран, демон без профиля
  отказывается запускаться под --seccomp, сознательно: whitelist не
  пишется из воображения.
- ci: .github/workflows/ci.yml, сборка, полный гейт, seccomp-профиль из
  strace на раннере, netns-атаки, cppcheck. локальный полный гейт зелёный
  включая побитовый детерминизм, party, статус-канал, ubsan.
- netns: tools/netns_setup.sh / netns_teardown.sh; в песочнице unshare и
  netns запрещены (нет cap_net_admin), тест помечен SKIP громко, это
  заранее объявленный в р1 провал площадки, а не кода.

## бенчмарки (results/benchmark.csv, loopback)

| сценарий | cpu | rss | throughput | latency |
|---|---|---|---|---|
| idle | 7.0% | 3.4 mb | - | - |
| под атакой (scan 50/s) | 7.9% | 3.4 mb | - | - |
| throughput | - | - | 33.5 sessions/s | 1.5 ms |

пороги промта: idle < 1% cpu и < 10 mb, rss выполнен, cpu нет:
в realtime-режиме демон каждую секунду живёт 1 с модельного времени
(непрерывная симуляция нервной системы), 10 мс тик не бывает дешёвым;
порог < 1% осмыслен для архитектуры с событийным тикером (р3+).
throughput 33.5/s против > 100/s: узкое место: однопоточный
realtime-цикл с сенсором, не клиенты (проба на 8 потоках); требует
оптимизации (батч-accept, вынесение симуляции из тика). latency 1.5 ms
выполнен. rss под потолком 16 mb выполнен с запасом.

## сессия 5, инсайдер

seccomp ограничивает syscall-поверхность демона, но не сигналы: инсайдер
с тем же uid остановит процесс kill'ом. проверка "может ли атакующий
убить proteusd" в этой модели угрозы переносится на владельца сервиса
(системная единица с ограничениями, отдельный uid), вне рамок р2.

## отклонения от промта, зафиксированные

1. replace tcp_port_move with nftables_rules: полная замена невозможна
   в непривилегированной среде; р2 реализует nft-бэкенд поверх
   userspace-листа с громкой деградацией, замена станет дефолтом на
   привилегированном стенде.
2. syn на закрытые порты видит только ядро: без nfqueue сенсор
   реагирует на соединения, дошедшие до открытого порта окна; полный
   сенсор требует libnetfilter_queue, это вне списка зависимостей р2.
3. настоящий tarpit ядром nftables не выражается; в р2 старый порт
   уходит из принятия соединений, вязкий слой отложен до р3 с
   userspace-заглушкой в духе endlessh.

## валидация на реальном железе

инструмент `sudo tools/validate_r2.sh`: шесть фаз (netns-атаки,
nftables, seccomp из strace, бенчмарки, красная команда, end-to-end),
сырые данные в results/r2_validation/raw_data, манифест sha256
(manifest.txt), человекочитаемый отчёт (report.md) с вердиктом по
критериям: все critical зелёные и >80% important, r2 validated.
быстрый прогон: BENCH_DUR=120 DET_DUR=120 sudo tools/validate_r2.sh.

самопрогон в песочнице (фазы 4-5, без root) закрыл контур: детерминизм
побитовый, throughput 252 sessions/s (порог 100 превзойдён пробой,
учитывающей порт; прежние 33.5 были артефактом пробы в мёртвый порт),
latency p99 1.8 ms, rss стабилен под нагрузкой 500/s.

находка красной команды (self-test): детекция targeted-скана в сетевых
условиях ниже fixture-оценки р1: 1/3 сессий при пороге 30 (fixture
7-8/10); одиночные импульсы и адаптация ava против sustained-пачки
фикстуры. порог заморожен, rate публикуется как измерение; атлас р3
обязан мерить детекцию в сетевых условиях отдельно от fixture-прогона.
механизм бана держит: 0 сессий после строки бана во всех случаях.

дополнительные зазоры после self-test: пользователи run_attack_scenarios.sh
должны учитывать, что при переносе порта генераторы с фиксированным
первым портом промахиваются; в validate_r2.sh пробы перечитывают
порт из статус-канала.
